# DevPulse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build DevPulse, a menu-bar-only macOS app with a live lazygit-style terminal UI and a
hotkey launcher. It shows my GitHub PRs and review requests, my Jira Cloud tickets and my running
Claude Code sessions, and notifies me about what needs me.

**Architecture:**
- **The Swift menu bar app is the only process that fetches or watches data.** It polls GitHub and
  Jira on an interval, and it watches `~/.claude/sessions` for file changes instead of polling. It
  keeps one `Snapshot` and sends notifications.
- **It publishes the `Snapshot`** as newline-delimited JSON over a Unix-domain socket.
- **`devpulse` is a thin client.** It is a Rust/ratatui binary bundled in the app; it renders the
  snapshot and sends commands (refresh, open, upgrade).

**Tech Stack:**
- Swift 6.4, SwiftUI `MenuBarExtra`, AppKit (`NSPanel`), Carbon hotkey,
  `UserNotifications`, `ServiceManagement`, Sparkle 2, Swift Testing;
- Rust (edition 2024) with `ratatui`, `crossterm`, `serde`, `serde_json`;
- the `new-macos-app` skill pipeline (SwiftPM + `build.sh`, Developer ID + notarized DMG, GitHub
  Pages).

**Spec:** `docs/superpowers/specs/2026-11-19-devpulse-design.md`. Read it before any task.

## Global Constraints

**Platform and naming:**
- The minimum macOS is **27**: `.macOS(.v27)` and swift-tools-version 6.4. The binaries are
  arm64 only.
- `APP` = `DevPulse`, `APP_NAME` = `DevPulse`, `APP_LOWER` = `devpulse`, bundle ID
  `io.jp4.devpulse`. The core target is `DevPulseCore`; its tests are in `DevPulseCoreTests`.
- **Case-insensitive APFS:** the app executable `Contents/MacOS/DevPulse` and the CLI `devpulse`
  must not share a directory. The CLI lives at **`Contents/Helpers/devpulse`**.

**UI and behavior:**
- The UI is English. The app is menu bar only (`LSUIElement` = true), unsandboxed.
- The refresh interval defaults to **120 s**; the allowed range is 60–1800 s.
- Fetching pauses while the Mac sleeps or the screen is locked, and fetches once on wake or unlock.
- Notification triggers and their defaults are exactly spec §2.2:

  | Trigger | Default |
  |---|---|
  | direct review request | on |
  | team review request | off |
  | PR human comment | on |
  | PR Copilot comment/review | on |
  | PR other bot comment | off |
  | CI finished (success/failure/error) | on |
  | Jira human comment | on |
  | Jira automation comment | off |
  | Claude → `waiting` | on |
  | Claude `busy` → `idle` | on |

  Each source (GitHub, Jira, Claude Code) also has a master switch.
- My own comments never notify. The first fetch of a source only records what exists and never
  notifies. Each event notifies only once.

**IPC and storage:**
- Socket: `~/Library/Application Support/DevPulse/devpulse.sock`, mode 0600. Protocol version
  **1**, newline-delimited JSON.
- The Jira API token goes into the Keychain (service `io.jp4.devpulse.jira`). The GitHub token
  comes from `gh auth token` and stays in memory only.

**Repo rules:**
- Every user-visible change adds a line under `## Unreleased` in `CHANGELOG.md`.
- Every `docs/` page change goes into `docs/cs/` too.
- Git: run `git status` before every commit. Never add AI attribution trailers. **Never create the
  GitHub repo or `git push` without asking the user first, in bold.**

## Review Focus

1. **The app runs from the DMG or a translocated path.** "Install command line tool" must refuse
   unless the app is in `/Applications` (or `~/Applications`), and say why. Otherwise the symlink
   points at a path that disappears. *Test in Task 12.*
2. **A stale or garbage session file:** a dead PID, a reused PID that is not `claude`, a partial or
   unparseable JSON written mid-update, or an unknown `status`. The list must not show ghosts or
   crash; an unknown status shows as `unknown`. *Tests in Task 3.*
3. **Network failure or expired credentials:** GitHub 401 (refresh the token from `gh` once, then
   report), Jira 401/403, or offline. The last good data stays visible with its age and an error
   state; nothing is wiped, and the failure fires no notifications. *Tests in Tasks 6 and 7.*
4. **Long, diacritic-heavy titles in a narrow terminal**, e.g. "Přehled příliš žluťoučkých koní
   úpějících ďábelské ódy na nádvoří" at 80 columns. They truncate with `…` and never
   panic. A terminal smaller than 60×15 shows a "terminal too small" message. *Tests in Task 14.*
5. **The app quits or restarts while the TUI is open** (including during `devpulse upgrade`). The
   TUI shows "disconnected — reconnecting…", retries every 1 s, and restores its selection by item
   ID after reconnecting. *Tests in Tasks 13 and 15.*

## Shared data model (defined in Task 2, mirrored in Rust in Task 13)

The JSON contract is `protocol/fixtures/snapshot-v1.json`. Both sides must decode it and agree on
it. Dates are ISO 8601 strings, enums are lowerCamel strings, and optional fields may be absent.

```
Snapshot        { appVersion: String, generatedAt: Date, jiraBaseURL: String?,
                  sources: { github: SourceStatus, jira: SourceStatus, claude: SourceStatus },
                  myPullRequests: [PullRequest], reviewRequests: [PullRequest],
                  tickets: [Ticket], sessions: [ClaudeSession] }
SourceStatus    { state: ok|fetching|error|disabled|unconfigured, lastSuccess: Date?, message: String? }
PullRequest     { id: String (GraphQL node id), repo: String "owner/name", number: Int, title, url,
                  headBranch, headOid, jiraKey: String?, checks: none|pending|success|failure|error,
                  reviewDecision: none|reviewRequired|approved|changesRequested,
                  approvals: Int, pendingReviewers: Int, commentCount: Int, lastCommentAt: Date?,
                  requestedDirectly: Bool, updatedAt: Date, recentComments: [Comment] }
Ticket          { key, summary, status, statusCategory: todo|inProgress|done, priority: String?,
                  url, updatedAt: Date, commentCount: Int, lastCommentAt: Date?, recentComments: [Comment] }
Comment         { id: String, author: String, authorKind: human|bot|copilot, createdAt: Date }
ClaudeSession   { pid: Int, name, cwd, status: busy|waiting|idle|unknown, waitingFor: String?,
                  jiraKey: String?, updatedAt: Date }
```

Messages over the socket:

| Direction | Message |
|---|---|
| server → client | `{"type":"snapshot","protocol":1,"data":Snapshot}`. It is sent on connect and after every change; the whole snapshot is sent each time, since it is small. |
| server → client | `{"type":"upgrade","phase":"checking"\|"downloading"\|"installing"\|"restarting"\|"upToDate"\|"failed","progress":0.0-1.0?,"message":String?}` |
| client → server | `{"type":"hello","protocol":1}` |
| client → server | `{"type":"refresh"}` |
| client → server | `{"type":"openSettings"}` |
| client → server | `{"type":"upgrade"}` |
| client → server | `{"type":"open","kind":"pr"\|"ticket"\|"session"\|"jiraForPr","id":String}` |

The `id` in `open` is: the PR `id` for `pr` and `jiraForPr`, the ticket `key`, or the session
`pid` as a string.
